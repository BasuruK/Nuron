## 2026-06-19 — Brief creation session (Basuruk + facilitator)

### D-001 · Intent & stakes
- Brief mode: **create**.
- Stakes: **D — greenlight to Nuron team + engineering** (internal MVP scope alignment, not investor pitch).

### D-002 · Audience & consumption shape
- Primary runtime consumer: **agents and admins**.
- Frontend posture: **Laravel + ShadCN presentation layer is one possible client, not the product.** Nuron ships APIs + auth; the frontend is replaceable.

### D-003 · v1 hosting shape
- v1 is **self-hosted, single-tenant**.
- The customer deploys and operates their own Nuron instance.
- Multi-tenant control plane (managed Nuron-as-a-service) is a **v2** business possibility. v1 includes the *primitives* (tenant_id scoping, isolated data directories) so v2 doesn't require a rewrite.

### D-004 · v1 agent model
- v1 ships **one Nuron-maintained default agent** + **user-configured agents created from Nuron-supplied templates**.
- Freeform agent authoring / custom LangGraph graphs is **explicitly a v1 non-goal**.

### D-005 · Decision-graph semantics
- "Decision" in v1 = **a human commitment captured in markdown / docs / conversation**, with explicit supersession.
- Agent responses are *grounded in* the decision graph; they are not themselves first-class decisions unless an explicit commit action is taken.
- The headline product claim is **decision lineage** — A → B → C chains with attribution and timestamp — not generic entity-relationship RAG.

### D-006 · Graph evolution strategy
- Strategy: **Snapshot + diff** curation.
- Optimisation hypothesis (file in addendum): a Merkle-tree-like index over subtrees so only recently-touched branches are re-curated. Hypothesis to be pressure-tested in `[CA]`.

### D-007 · v1 source ingest scope
- v1 ingest = **Markdown files in a defined location** (the spine).
- Confluence / Jira / Forum connectors are **v1.1** work, not in the v1 brief scope.
- Brief will note explicitly that v1 proves the pipeline + retrieval, and that source-connectors are the work that turns the pipeline into the company-brain value claim.

### D-008 · v1 auth model
- **Built-in user store with admin-provisioned accounts** (option b).
- Entra / OIDC / SAML SSO deferred to v1.1+.

### D-009 · Continuity claim as moat
- The brief's "what makes this different" pillar is **institutional continuity across human turnover**, not technical moats.
- Source: the user's own framing — "what if I leave the office? can another person go through all my 20 years worth of content and explain or teach someone new?"

### D-010 · Open Questions captured for the brief
- Q-A: GCP vs Azure (and other providers) for the future managed service. Pricing-volatile, treated as **Open**, not a decision.
- Q-B: v1 source-connectors — confirm one real source is in v1, not only markdown files (see D-007).
- Q-C: Whether the default agent's "reply" action posts back to the originating forum or only returns via API.
- Q-D: Per-tenant data retention / GDPR posture for v1.

## 2026-07-06 — Brief revision session (Basuruk + facilitator)

### D-012 · Stack split — Laravel (backend) + Svelte (frontend)
- **Decision:** v1 ships **Laravel as the backend (REST API + auth surface)** and **Svelte (SvelteKit) as the frontend (reference admin UI)**. Laravel is no longer the frontend hosting surface; ShadCN is no longer in the picture because it is a React ecosystem.
- **Rationale:** API-first posture. The brief already commits that the contract is the API and auth surface, not the UI. SvelteKit keeps the frontend as a thin client over the Laravel REST API; Laravel stays purely on the backend side.
- **Supersedes:** the previous framing where Laravel was the backend framework *and* the frontend hosting surface (serving Blade + React/ShadCN).
- **Cross-refs:** `brief.md` §"Frontend Stack Decision"; §"Executive Summary"; §"Deployment topology".

### D-013 · Frontend primitives — Bits UI is the default; shadcn-svelte is the revisit option
- **Decision:** Svelte is locked (D-012). Frontend primitives default to **Bits UI**. **shadcn-svelte** is the "consider revisiting" option if visual velocity becomes more important than dependency count.
- **Rationale:** Bits UI is headless and styling-agnostic (matches the brief's "frontend is not the product" posture); ships first-party a11y; low switching cost if primitives change later. shadcn-svelte is a closer 1:1 swap for the previous ShadCN choice but requires Tailwind and copies styled components into the repo.
- **Cross-refs:** `brief.md` §"Frontend Stack Decision"; Open Question **Q-F**; Addendum (no separate addendum section; comparison is in the brief).
- **Lock-in:** PRD / Architecture must lock Bits UI vs shadcn-svelte before the frontend epic is broken down.

### D-014 · Styling is not a top-level decision
- **Decision:** Styling follows the primitives choice (D-013). **Svelte's built-in scoped CSS is the default** styling layer. Tailwind CSS is opt-in, and is *required* only if the primitives choice lands on shadcn-svelte.
- **Rationale:** Bits UI does not require Tailwind. Forcing Tailwind into the brief when Bits UI is the default would add an unnecessary dependency. Svelte's built-in scoped CSS provides automatic scoping, dead-code elimination, and zero runtime overhead.
- **Cross-refs:** `brief.md` §"Frontend Stack Decision → Styling posture"; §"What stays, what changes" table.

### D-015 · Deployment topology — API + Web in separate containers
- **Decision:** v1 ships the API and the Web as **separate containers** in the self-hosted Docker / compose stack. At minimum: `nuron-api` (Laravel, internal network only), `nuron-web` (SvelteKit, public-internal edge), data plane (Neo4j, optional RabbitMQ per D-018, compiler workers, cache — internal network only).
- **Rationale:** Keeps Laravel purely on the backend; lets the frontend be replaced wholesale without touching the API container; mirrors the Docker Compose profile model used by Cognee (`ui / mcp / postgres / neo4j`).
- **Cross-refs:** `brief.md` §"Frontend Stack Decision → Deployment topology"; Open Question **Q-J**; Addendum **§K. Deployment Topology Notes**.

### D-016 · Decision lineage is modelled at write time (not just at retrieval time)
- **Decision:** v1's data model commits to **explicit supersession edges at write time**, with every derived fact tracing back to a raw episode as the lineage anchor. Contradictions between new evidence and prior decisions are reconciled as a first-class outcome of the curator pass, not silently averaged away.
- **Rationale:** The competitor analysis showed that Graphiti's bi-temporal `valid_at` / `invalid_at` is the strongest existing supersession story (Mem0's v3 does retrieval-time ranking only; Cognee has no explicit decision entity). Modelling supersession at write time is the differentiator and the moat for the brief's "Decision lineage, not generic RAG" pillar.
- **Cross-refs:** `brief.md` §"What Makes This Different" Pillar #2; Addendum **§H.6** (lessons from Graphiti); **§H.7** (implication #3).
- **Lock-in:** Architecture phase confirms the exact supersession-edge schema and the curator contradiction-reconciliation protocol.

### D-017 · No telemetry by default (open-core procurement posture)
- **Decision:** v1 ships with **no telemetry by default** — no usage analytics, no error reporting, no model-call traces leaving the customer's network. The only outbound network traffic is whatever the customer explicitly configures (LLM provider, embedding provider).
- **Rationale:** Competitor analysis showed Graphiti ships PostHog telemetry on by default (opt-out via env var), and both Mem0 and Cognee include analytics hooks in their self-hosted server images. Enterprise procurement will flag all three. No-telemetry-by-default is a cheap, durable, procurement-friendly differentiator that matches the brief's "self-hosted, customer-controlled" posture.
- **Cross-refs:** `brief.md` §"What Makes This Different" Pillar #4; Addendum **§H.4** (Graphiti gap); **§H.7** (implication #6).

### D-018 · Async pipeline default — in-process with RabbitMQ opt-in
- **Decision:** v1 defaults to an **in-process async pipeline** (mirrors Cognee's `run_in_background` toggle) with an explicit `NURON_QUEUE_MODE=in-process | rabbitmq` config flag for opt-in RabbitMQ.
- **Rationale:** RabbitMQ is a real durability / scaling story (none of Mem0 / Cognee / Graphiti run an external broker — all three are in-process). But it is also an ops tax for self-hosters. v1's customer base (one company brain per deployment) is unlikely to hit backpressure problems in the first 12 months. RabbitMQ becomes the default if/when multi-tenant managed service ships in v2.
- **Cross-refs:** `brief.md` §"What Makes This Different" Pillar #3; Open Question **Q-I**; Addendum **§I. Async Pipeline Trade-offs**.
- **Lock-in:** Architecture phase confirms the queue-mode flag, the in-process pipeline executor's contract, and the migration path from in-process → RabbitMQ for v2.

### D-019 · Tenant scoping — flat filter key for v1 (defer RBAC)
- **Decision:** v1 adopts Mem0's flat filter-key pattern as the scoping model (e.g. a single `workspace` or `team` scoping key). Cognee-style RBAC is deferred until v2 multi-tenant.
- **Rationale:** v1 is single-tenant per deployment. Flat filter keys are lighter, more agent-friendly (agents can self-scope via filter values), and avoid the configuration surface of RBAC. Mem0's model (`user_id` / `agent_id` / `app_id` / `run_id`) is the working precedent.
- **Cross-refs:** Open Question **Q-H**; Addendum **§H.7** (implication #4).
- **Lock-in:** Architecture phase confirms the exact scoping key names and the per-tenant data directory layout (see existing addendum §D).

### D-020 · OpenClaw / agent-platform plugin deferred from v1
- **Decision:** Nuron does **not** ship an OpenClaw plugin in v1. v1 priorities are: LangGraph agents (Nuron's own compiler) first, MCP second; an OpenClaw plugin only ships if user demand materialises post-v1.
- **Rationale:** Mem0 and Cognee both ship OpenClaw plugins; the agent-platform plugin layer is crowded. v1's spine is the LangGraph compiler + property graph + runtime query path; an OpenClaw plugin would add a fourth top-level surface area (plugin authoring, distribution, lifecycle) without addressing the wrong seam (Nuron's value is the graph + lineage, not the tool surface).
- **Cross-refs:** `brief.md` §"Explicit non-goals"; Addendum **§L. Why OpenClaw / Agent-Platform Plugins Are Deferred**.

### D-021 · Embedding model floor — ≥ 600M params / ≥ 1024 dim
- **Decision:** v1 ships a **recommended embedding model floor** — ≥ 600M parameter class with ≥ 1024-dim output, with a quality bar (must produce semantically meaningful similarity on enterprise-shaped text). The default for v1 is an OpenAI-class hosted embedding model (e.g. `text-embedding-3-large`, 3072 dim), with a local-model option for self-hosted deployments.
- **Rationale:** Mem0's README recommends ≥ Qwen 600M for hybrid search; Graphiti's default `EMBEDDING_DIM=1024` is the working consensus. Decision-lineage retrieval depends on entity / decision similarity working well enough that supersession candidates surface.
- **Cross-refs:** `brief.md` §"Recommended embedding model floor"; Addendum **§J. Embedding Model Floor — Rationale**.
- **Lock-in:** Architecture phase pins the exact model, dimensions, and self-hosted-vs-hosted default.

### D-022 · The Problem was sharpened with a domain / people / systems mental model
- **Decision:** The Problem section now includes a **Mental model** paragraph + an ASCII diagram of "Domain A / Domain B / Scattered across domains, flows, people, and systems," and three symptom bullets (people touching non-specified areas to learn; cross-functional knowledge living in people; operational + people-handling knowledge treated as out of scope by other tools).
- **Rationale:** Drawn from the user's handwritten "Core truths" notes (2026-07-06). Enterprise knowledge is fragmented by *structure* (domains / flows / people / systems), not just by content volume. The previous brief framing implied this but did not foreground it. The new framing makes the cross-functional and operational-knowledge scope explicit, which is the brief's coverage claim against competitors like Cognee and Mem0.
- **Cross-refs:** `brief.md` §"The Problem → Mental model"; §"The Solution" (uniform treatment of testing flows and operational knowledge).

### D-023 · License correction (Graphiti is Apache-2.0, not BSL)
- **Decision:** The brief is corrected to state that **all three competitors (Mem0, Cognee, Graphiti) are Apache-2.0**. Graphiti's commercial wrapper is the Zep SaaS product, not the open-source graph engine.
- **Rationale:** Verified against the LICENSE files in all three repos. Self-hosted distribution is not blocked by licensing. The real risk is being tied to a *managed wrapper vendor*'s roadmap (Zep, Cognee Cloud, Mem0 Platform) — captured as Open Question **Q-G**.
- **Cross-refs:** `brief.md` Open Question **Q-G**; Addendum **§H.1** (license row), **§H.7** (implication #1).
