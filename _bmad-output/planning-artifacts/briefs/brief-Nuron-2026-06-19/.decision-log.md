## 2026-06-19 — Brief creation session (Basuruk + facilitator)

### D-001 · Intent & stakes
- Brief mode: **create**.
- Stakes: **D — greenlight to Nuron team + engineering** (internal MVP scope alignment, not investor pitch).

### D-002 · Audience & consumption shape
- Primary runtime consumer: **agents and admins**.
- Frontend posture: **Laravel + ShadCN presentation layer is one possible client, not the product.** Nuron ships APIs + auth; the frontend is replaceable.

### D-003 · v1 hosting shape
- v1 is **self-hosted, single-tenant**.
- The customer deploys and operates their own Nuron instance.
- Multi-tenant control plane (managed Nuron-as-a-service) is a **v2** business possibility. v1 includes the *primitives* (tenant_id scoping, isolated data directories) so v2 doesn't require a rewrite.

### D-004 · v1 agent model
- v1 ships **one Nuron-maintained default agent** + **user-configured agents created from Nuron-supplied templates**.
- Freeform agent authoring / custom LangGraph graphs is **explicitly a v1 non-goal**.

### D-005 · Decision-graph semantics
- "Decision" in v1 = **a human commitment captured in markdown / docs / conversation**, with explicit supersession.
- Agent responses are *grounded in* the decision graph; they are not themselves first-class decisions unless an explicit commit action is taken.
- The headline product claim is **decision lineage** — A → B → C chains with attribution and timestamp — not generic entity-relationship RAG.

### D-006 · Graph evolution strategy
- Strategy: **Snapshot + diff** curation.
- Optimisation hypothesis (file in addendum): a Merkle-tree-like index over subtrees so only recently-touched branches are re-curated. Hypothesis to be pressure-tested in `[CA]`.

### D-007 · v1 source ingest scope
- v1 ingest = **Markdown files in a defined location** (the spine).
- Confluence / Jira / Forum connectors are **v1.1** work, not in the v1 brief scope.
- Brief will note explicitly that v1 proves the pipeline + retrieval, and that source-connectors are the work that turns the pipeline into the company-brain value claim.

### D-008 · v1 auth model
- **Built-in user store with admin-provisioned accounts** (option b).
- Entra / OIDC / SAML SSO deferred to v1.1+.

### D-009 · Continuity claim as moat
- The brief's "what makes this different" pillar is **institutional continuity across human turnover**, not technical moats.
- Source: the user's own framing — "what if I leave the office? can another person go through all my 20 years worth of content and explain or teach someone new?"

### D-010 · Open Questions captured for the brief
- Q-A: GCP vs Azure (and other providers) for the future managed service. Pricing-volatile, treated as **Open**, not a decision.
- Q-B: v1 source-connectors — confirm one real source is in v1, not only markdown files (see D-007).
- Q-C: Whether the default agent's "reply" action posts back to the originating forum or only returns via API.
- Q-D: Per-tenant data retention / GDPR posture for v1.
